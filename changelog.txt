= 1.19.1 =
* Fixed: the move from SEO Pro Stats on an admin page or scheduled-jobs run no longer stops with a fatal error on a site with stored connection credentials or shared reports. It ran as the plugin's main file was included, before WordPress defines wp_salt(), which the credentials' key needs; the tables and options had moved, the plugin stayed off (no tracker, WP-CLI with migrate-name only), and each admin page or cron run after the lock's 10 minutes stopped the same way. The move now runs first thing on plugins_loaded, and the plugin loads on that request, so a cron run has the moved jobs' callbacks. A site left part way by 1.19.0 finishes on its first admin page or cron run after the lock's 10 minutes, or straight away with wp option delete seoproanalytics_rename_lock and wp seoproanalytics migrate-name.
* Fixed: wp seoproanalytics migrate-name waits, up to a minute, while an admin page or cron run is moving a site's data, then runs again for what is left, so scripts/move-install.sh checks the row counts after the move. A run that finds another request's lock no longer stores "Another request is moving this site's data" as a note shown to administrators after the move.

* Changed: SEO Pro Stats is now SEO Pro Analytics (seoproanalytics): the folder and main file (seoproanalytics/seoproanalytics.php), classes (SEOProAnalytics_), constants (SEOPROANALYTICS_), options, tables, hooks, meta keys, the REST namespace seoproanalytics/v1, wp seoproanalytics, the abilities, the capability view_seoproanalytics, the share parameter seoproanalytics_share, the A/B test block names, the collector folder wp-content/seoproanalytics and the CSS prefix seoproan. The old names are not kept as aliases. Checked with that script on WordPress 7.1 with PHP 8.3, on a single site and on a network of two sites with its own encryption key, from SEO Pro Stats 1.17.1 and 1.18.0 with demo data, a connection with encrypted state and a shared report with link and password copies, each read back unchanged after the move; and earlier, also through wp-admin, from 1.11.0 with an A/B test, order meta and unprocessed hits.

= 1.17.0 =
* Changed: the Trend switch on the Overview, Search → Rankings and Page experience charts is Off, Short or Long instead of one line of 1, 4, 13 or 52 weeks. Each draws two trailing moving averages: Short a 1-week against a 13-week average, Long a 4-week against a 52-week one. The long-term line is the text colour; the short-term line is green where it is better than the long-term one and red where it is worse, split exactly where the two cross (straight lines between points), and the faded text colour where there is no long-term average yet. Better follows the metric: higher for counts, views per visit, visit duration and CTR; lower for average position (higher on its upside-down axis), bounce rate and Core Web Vitals. A window needs two points at the chart's grain: on weekly charts the short-term average is 4 weeks, monthly charts offer Long only (13 against 52 weeks), hourly charts have no switch. One history request (the long window's days) serves both lines. The tooltip gives both averages, its swatch in the colour at that point; the screen-reader table has a column for each. The choice is kept in the browser under a new key, so an earlier choice starts Off.

= 1.10.0 =
* New: Needs links (Search → Backlinks): pages whose searches sit at positions 4–20 and that have fewer useful referring domains (sites with a followed link not classed Ignore, Spam, Profile Page or Social Media) than the median of the site's pages in the top three. Highest need first: the clicks within reach in the top three × that gap. Each names its best searches. Pages that need links are also Plan items, scored as striking distance (confidence 0.4, effort 3), once backlinks have been read.
* New: Link impact (Search → Backlinks): each page that gained useful referring domains in the period, with the new sites and the page's search clicks, impressions and position per day in the 28 days before and from the first, against the whole site. It shows what changed alongside the links, not proof they caused it; Start an experiment measures the page against pages left alone from its new-link change.
